## API选择

抖音提供多种API接口，可以根据情况选择：

| 接口类型         | 说明                                                   |
| ---------------- | ------------------------------------------------------ |
| web直播间接口    | 效果不错，支持双屏直播参数                             |
| mobile直播间接口 | 不易风控，也许支持电台直播，对IP有要求，不会应用Cookie |
| 直播间web解析    | 易风控，有验证码，单个接口1M流量                       |
| 用户web解析      | 不易风控，海外IP无法使用，单个接口1M流量               |
| 负载均衡         | 使用负载均衡算法来分摊防止风控                         |
| 随机             | 从几个接口里挑一个                                     |

::: tip 提示
`mobile直播间接口` 及 `用户web解析` 只对 `3.1.0` 及之后添加的直播间有效。
:::

## Cookie模式

支持全局配置，也可以为单个录制器单独设置，默认为“全部”。

- 全部：Cookie 用于直播状态检测、取流和弹幕连接。
- 仅流：Cookie 仅用于直播状态检测和取流。
- 仅弹幕：Cookie 仅用于弹幕连接。

mobile 接口在直播状态检测和取流时仍不会应用 Cookie。

## 连麦主播名单

在“设置 → 录制 → 抖音”中开启“记录连麦主播”。这是全局开关，默认关闭，不提供单个直播间覆盖；修改后从下一次录制生效。

开启后会记录录制期间发现的其他连麦、PK 主播，排除主播本人和普通上麦观众。每行保存首次发现时间、昵称、抖音号、UID 和主页。时间采用服务器或桌面程序所在时区。

名单以 UTF-8 文本保存到首次录像文件所在目录，例如首次录像为 `主播_开录时间-PART000.ts`，名单为 `主播_开录时间-PART000.连麦记录.txt`。没有发现主播时不创建空文件。

一次录制内按主播身份去重，视频分段和消息重连不重置名单；后续分段即使保存到其他目录，也继续使用第一份名单。停止后重新开始录制会重新统计。

即使关闭弹幕保存，开启此功能仍会连接消息服务，但不会保存普通弹幕和礼物。消息连接继续遵循 Cookie 模式。

名单解析或写入失败不影响视频录制，错误会显示在日志和录制时间线中；未写入的主播会保留到后续消息、视频分段或停止录制时重试。停止时的最后补写最多等待 3.5 秒，仍未保存会提示。

::: tip 识别范围
首版沿用原补丁对连麦、PK 消息的识别规则，平台协议变化可能导致漏记或误记，仍需通过实际直播验证。名单不是完整上下麦时间线，不提供连麦次数和持续时长。
:::

# 常见问题

## 抖音双屏录播如何分割主画面？

假设已开启"双屏直播流选项"，主画面分辨率为 1920x1080。

在 `ffmpeg设置` 的 `视频滤镜` 中输入：

```
crop=1920:1080:0:0;$origin
```

## 弹幕无法录制

弹幕服务器存在单独风控，家宽请尝试重启光猫更换IP，或者大约等待两天可恢复

## 礼物弹幕无法录制

尝试设置cookie

## 抖音风控怎么办？

1. 调大检查间隔
2. 修改“并发数”为1
3. 调大“等待时间”为1000ms
4. 修改使用的api接口
